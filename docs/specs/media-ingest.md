# メディアインジェスト

## What Should Be Built

音声 / 映像を抽出し、コンテナ / コーデック / タイミング情報を十分に
記録して、キャプチャ由来のアーティファクトとゲーム音声の挙動を
区別できるようにするインジェスト層。

入力:

- 映像キャプチャファイル
- 音声のみのソース素材
- 任意のツール / ゲーム設定とインジェスト辞書

必須の音声メタデータ:

- コーデック / コンテナ
- サンプルレート
- サンプルフォーマット / ビット深度(取得可能な場合)
- チャンネル数 / レイアウト
- ストリーム開始 / 終了タイムスタンプ
- パケットタイムスタンプとパケット長
- デコーダ / リサンプラ設定
- 検出した不連続・ギャップ・オーバーラップ
- 元ファイルのハッシュ

必須の映像メタデータ:

- コーデック / コンテナ
- フレーム PTS / DTS(取得可能な場合)
- フレーム間隔系列
- 公称 vs 実測 / VFR フレームレート
- 重複 / ドロップフレーム候補
- ストリーム開始 / 終了タイムスタンプ

キャプチャ完全性の観測(診断ではなく観測を永続化する):

- タイムスタンプ不連続
- 欠落 / 重複パケット候補
- デコードで生じた無音 / ゼロ区間
- チャンネルレイアウトの不整合
- ツールが行ったリサンプリング
- 非可逆コーデックの存在
- 既知のコーデック / キャプチャ帯域制約

キャプチャアーティファクト辞書(バージョン管理された辞書を提供し、
後段解析がクエリできる):

- コーデックの高域カットオフの期待範囲
- 既知のコンテナ / コーデックのブロックサイズ
- 想定されるサンプルレート変換経路
- ユーザー提供のキャプチャデバイス / 録画プリセット

この辞書はカットオフ等の観測への注釈に使い、生の計測を抑制するためには
決して使わない。

デコードポリシー:

- 正規化前のデコード済み PCM を保存する
- すべての正規化 / リサンプリング操作を記録する
- 破壊的なモノラルダウンミックスをデフォルトにしない
- 音声と映像のクロックを個別にアドレス可能に保つ

## Why Now

後段のあらゆる計測は「この信号はどうデコードされたか」に依存する。
デコード経路とタイミング完全性を最初に固定しないと、後から原因を
キャプチャ側とゲーム側に切り分けられない。

## Users and Value

- 解析者: 観測されたカットオフやブロック周期性がインジェスト既知の
  録画アーティファクトと一致するかを照会できる
- 下流ステージ: CFR を仮定しない A/V タイムスタンプ対応付けが可能

## Scope

### In Scope

- 音声 / 映像のデコードと上記メタデータの取得・永続化
- 完全性観測の記録
- キャプチャアーティファクト辞書(バージョン付き)
- デコードポリシーの遵守

### Out of Scope

- 観測から原因を診断するロジック
- ゲーム / エンジン固有のデコード知識のハードコード

## Requirements

- インジェスト出力はメディアがどうデコードされたかを完全に説明できる
- A/V タイムスタンプは CFR を仮定せず対応付けできる
- 辞書は観測の注釈のみに使い、生計測を上書きしない

## Acceptance Criteria

- [ ] インジェスト出力からデコード手順を正確に説明できる
- [ ] A/V タイムスタンプを CFR 仮定なしに対応付けられる
- [ ] 観測されたカットオフ / ブロック周期性がインジェスト既知の録画
  アーティファクトに一致するか後段解析から照会できる

## Deferred Design Concerns

- 対応コンテナ / コーデックの範囲と辞書の初期内容 | 使用デコーダの
  選定に依存 | 開発環境決定時 | 対応範囲不足による入力拒否

## Sources and Relations
